# Hopper Arbitrary-Mask FA3 Merge Validation

Date: 2026-04-30

This note records the current design and validation status for merging the
Hopper arbitrary-mask FA3 path into the main `flash-attention` package.

## Scope

This merge brings the arbitrary-mask Hopper implementation into the FA3 package
used by downstream projects such as `attention-core`.

The target production use case is Gemma 4 sliding attention:

- head dimension: 256
- architecture: Hopper / SM90
- mask type: arbitrary sparse block metadata generated by the caller
- downstream full-attention layers with head dimension 512 remain on
  FlexAttention, because FA3 supports head dimension up to 256.

## Design

### Arbitrary-Mask Dispatch

The FA3 Python interface routes arbitrary-mask varlen calls through
`FlashAttnVarlenArbitraryFunc`.

The arbitrary path accepts:

- q2k block-sparse metadata
- k2q block-sparse metadata for backward
- arbitrary function metadata

The Hopper launcher path dispatches to arbitrary-mask forward/backward kernels
when those metadata tensors are present.

### Compile-Friendly Forward Wrapper

`FlashAttnVarlenArbitraryFunc.forward` calls the Python `_flash_attn_forward`
wrapper instead of calling `flash_attn_3_gpu.fwd` directly.

This matters for `torch.compile` because the wrapper owns the registered
schema/fake implementation boundary. Passing arbitrary/block-sparse metadata
through the wrapper avoids exposing a raw extension op call with an incomplete
Python-side schema.

The installed compile-friendly package was verified to use:

```text
calls_wrapper: True
calls_raw_gpu: False
```

### Max Func Count

The build supports a configurable arbitrary-mask function upper bound:

```bash
FLASH_ATTENTION_MAX_NUM_FUNC=5
```

The current packaged build is compiled with max func count 5. Current intended
use is odd function counts up to the configured max. Even function counts remain
unsupported and should fail early.

### Tile Policy API

The package exposes `get_arbitrary_block_size(...)` so downstream code can query
the FA3 tile policy instead of hard-coding block sizes in Python.

Downstream `attention-core` uses this API when building reusable Gemma 4
arbitrary-mask metadata.

## Fixes Included

- Restored Hopper arbitrary-mask forward path in the main FA3 package.
- Restored arbitrary-mask backward and sink-related paths.
- Restored SM90 varlen backward dispatch coverage for hdim96 and hdim192.
- Added SM90 arbitrary max-function-count instantiations.
- Added compile-friendly wrapper plumbing for arbitrary/block-sparse metadata.
- Added `FLASH_ATTENTION_MAX_NUM_FUNC` build-time control.
- Added the arbitrary block-size query helper for downstream metadata builders.

## Current Limitations

- Hopper / SM90 only for the arbitrary-mask path validated here.
- Current package is compiled with `FLASH_ATTENTION_MAX_NUM_FUNC=5`.
- Even function counts are unsupported.
- FA3 head dimension limit remains 256. Gemma 4 full layers with head dimension
  512 must use another backend such as FlexAttention.
- Full Ulysses+AMFA `torch.compile` backward precision still needs downstream
  investigation in `attention-core`; AMFA fullgraph compile itself is validated.

## Merge Readiness Summary

The FA3 package-side arbitrary-mask merge is ready from the perspective of:

- Python API plumbing
- Hopper arbitrary-mask dispatch
- compile-friendly op boundary
- downstream AMFA inner-core compile coverage
- downstream non-compiled 8-GPU Ulysses+AMFA coverage

The remaining compiled Ulysses precision issue should be tracked downstream and
does not indicate a package-side arbitrary-mask FA3 graph-break regression.
